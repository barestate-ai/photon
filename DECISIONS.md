# Decisions

Every material decision, fail trigger, and deviation, with the evidence behind it.
Results are labeled "measured" (command and output kept under `.logs/`, which is not tracked) or "not run".

## D1 · 2026-10-28 · FT1 does not fire; CEF stays the engine
A planning spike built the CEF 156.0.14 wrapper as a SwiftPM C++ target with Command Line Tools only, embedded a windowed Alloy browser in an NSView, and received `Page.getLayoutMetrics` through `SendDevToolsMessage` (measured). cefclient ran with `--use-native` and `--use-views` (measured). The helpers ran sandboxed with ad-hoc signing (measured with `sandbox_check`).

## D2 · 2026-10-28 · Chrome fallback engine deferred
Agent code still depends only on `CDPTransport`. Chrome 155 over `--remote-debugging-pipe` was verified during planning (measured). The Chrome transport is built only if FT1 fires later. Note for implementers: move pipe file descriptors to 10 or higher before `dup2` onto fds 3 and 4.

## D3 · 2026-10-28 · Model routing
- `muse-spark-1.3`: agent loop, native computer tool, before/after outcome verifier.
- `muse-wonder-1.0`: optional text/function planner only. It rejects the `computer` tool with HTTP 400 (measured twice).
- `muse-spark-1.3-contributor`: synthetic fixture tests only. Meta may train on its inputs, so it never sees real browsing.
- Baseten `meta-models/muse-spark-open` (model id configurable): adapter only; live test not run (no key).
- Caps: $40 mission-wide and $3 per run, from returned usage, tracked in `.logs/spend.json`.

## D4 · 2026-10-28 · Real models in tests, no mock model server
Tests that need a model call the real Meta API, on fixtures, with `BARESTATE_LIVE_META=1`. Timeouts and malformed replies, which a real API cannot produce on demand, use small stubs inside unit tests. Without a key, live tests are reported "not run".

## D5 · 2026-10-28 · Connecting to the always-on Muse agent
Muse runs in Meta's cloud and cannot reach localhost. Photon exposes MCP over Streamable HTTP through the gateway at a Tailscale Funnel path mount (`/barestate` on the already-public port 10000; the prefix is stripped). The user adds it in Muse as a Custom Connector with a bearer token. Muse's MCP version is unknown, so the server answers both the legacy `initialize` handshake and the 2026-07-28 `server/discover` style. If Muse requires OAuth, the smallest OAuth flow it needs is added. The connector step is manual and documented in `docs/muse.md`.

## D6 · 2026-10-28 · Validation without moving the user's cursor
End-to-end tests post synthetic `NSEvent`s through the app's own `sendEvent` path, behind `--test-hooks`. They never post `CGEvent`s. Screenshots use `screencapture`.

## D7 · 2026-10-29 · Frontend update replaces the Ask Muse panel
The permanent Ask Muse panel from the original M4 is removed. It is replaced by one Spotlight-style Command-T launcher for URLs, web search, tab switching, and explicit task submission, with task status attached to the working tab. Approved design: Figma page "21 · Browser · Refined Daylight" (file dQrWf5iyqhwiHZNUKDDLwy, node 763-2). Horizontal and vertical tabs share one live tab collection; vertical tabs can be pinned, hidden, or revealed as a temporary overlay that does not move the page. Engine, `CDPTransport`, executor, control epochs, approvals, journal, MCP, remote access, security rules, and spending caps are unchanged.

## D8 · 2026-10-29 · Custom tab chrome, not native window tabs
Native `NSWindow` tab groups were considered to save code, but they cannot present a vertical sidebar over the same live tabs. Tabs are one model with two native AppKit presentations.

## D9 · 2026-10-29 · Remote tasks never take the Mac user's tab
A phone task runs in its own working tab, which the task owns. The Mac shows the active remote session and a disconnect control. Any local input takes over immediately through the control epoch.

## D10 · 2026-10-29 · Message loop: `CefRunMessageLoop`, not the external pump
The app runs `CefRunMessageLoop()` (`external_message_pump` off) with `BarestateApplication`, our `NSApplication` subclass that implements `CefAppProtocol`. The socket server (`app.sock`), the SIGTERM/SIGINT handlers and `Task`s on the main actor are all GCD main-queue sources, and they fire under this loop (measured: `make e2e` drives `app.status`, `test.ui` and `test.screenshot` over the socket, and `SIGTERM` quits with exit code 0 in under a second). Closing a browser needs the `DoClose` fix from the spike: `DoClose` detaches the view and returns true, otherwise `OnBeforeClose` never fires and `CefShutdown` hangs. Quit closes every browser first and calls `CefQuitMessageLoop` from the last `OnBeforeClose`. The external pump stays the fallback if the app ever has to own the run loop.

Other facts fixed by the scaffold (measured in `make e2e`, 7 tests): the sandbox is on for renderer, GPU and utility processes and off only for the browser process; no TCP listener and no `--remote-debugging-*` flag exist anywhere in the process tree; a run writes only to `--data-dir` (`profile/`, `barestate.sqlite`, `tmp/`, plus `app.sock` and `app.pid` while running). The system SQLite keeps `-wal`/`-shm` after the last close unless `SQLITE_FCNTL_PERSIST_WAL` is cleared, so `Store` clears it on release.

## D11 · 2026-10-29 · DevTools replies come from the raw message stream
CEF does not call `OnDevToolsMethodResult` for methods the browser process answers itself (measured: `Page.getNavigationHistory`, `Browser.getVersion`), and it can deliver those replies synchronously inside `SendDevToolsMessage`. The bridge therefore forwards every `OnDevToolsMessage` as raw bytes and `CDPChannel` parses it once (`id` is a reply, `method` is an event). `CDPChannel` registers the pending call before writing so a synchronous reply is not lost. One `CDPChannel` per tab implements `CDPTransport`; calls time out after 10 s.

Test hooks make the app look active: `BarestateWindow.alwaysKey` and `BarestateApplication.alwaysActive` (both off without `--test-hooks`), because the system will not activate an app started from a script and Chromium drops mouse input while the app is inactive. `test.click` calls `makeKey()` first, otherwise the first click is consumed as an activating click.

Observation keys: `documentKey` is `<frameId>:<loaderId>`, `viewportKey` is `<scrollX>,<scrollY>,<w>x<h>@<dpr>`. Each tab keeps its last 8 observations. `extract` runs in the isolated world `barestate`, which page scripts cannot see.

## D12 · 2026-10-29 · Acting by ref, the journal, and an engine that ignores occlusion
- **Pipeline order:** journal row (`pending`) → resolve ref in the observation → permission (`controller == .agent(session)`) → hold (test hook) → per-write `admit` → dispatch → read-back. A rejected ref or missing grant ends `failed` (`unknown-ref`, `not-interactive`, `not-editable`, `not-in-control`, `unknown-observation`); a stale action ends `cancelled` with `stale: epoch|not-in-control|documentKey|viewportKey`. `admit` checks epoch first, so a human takeover reads as `stale: epoch`.
- **Atomic admit:** every write reads the page keys, runs `admit` synchronously and calls `CDPChannel.send` in one stretch of main-actor code, with no suspension between the check and the write. `Dispatch` therefore takes the concrete `CDPChannel`, not `any CDPTransport`: a call through the existential would hop off the main actor before writing. A click's press and release are put on the wire together (`CDPChannel.submit`) after one admission, so a takeover cannot fall between them and the page never sees a button left down. Actions on one tab run one at a time, so another action's focus cannot land between a type's `DOM.focus` and `Input.insertText`.
- **Interim click verdict:** a click has no DOM read-back, so it ends `confirmed` with `dom_verdict = dispatched`. A type ends `confirmed` only if the field's value contains the text, else `failed`. The model verifier (§5.7) replaces this rule in `permissions-verified-outcome`.
- **Errors after a write may have landed** (timeout, closed channel) end `outcome-unknown`; nothing is retried. `pending` rows left by a previous run become `outcome-unknown` (`app-restarted`), reconciled only after the socket server has started, so a second launch against a live data directory fails first and leaves the journal alone. A type's read-back checks that the value contains the text, because `insertText` goes in at the caret of a possibly prefilled field.
- **`act` returns at the first stable point:** the final row, or the `pending` row while `test.holdDispatch` is on. `action_status` reports the rest. A repeat of (sessionId, clientActionId) returns the stored row.
- **Observe race:** `Observer` reads the page keys before and after the five collection reads and retries up to 3 times until they agree and match the observation's own keys; otherwise it fails with `unstable`.
- **Occlusion:** a window that macOS reports as not visible made Chromium hide the WebContents (`visibilityState = hidden`). The first document still took input, but every later cross-document navigation produced a hidden render widget that dropped both synthetic NSEvents and `Input.dispatchMouseEvent`. The browser now starts with `--disable-features=WebContentsOcclusion --disable-backgrounding-occluded-windows`, which an agent browser needs anyway, since it works while its window is behind others (measured: after the change, `visibilityState = visible` and a click after `Page.navigate` lands). `test.ui` reports `windowOnScreen` to diagnose this.

## D14 · 2026-10-29 · Typing is bound to the requested node; observe titles come from the snapshot
- **Focus binding:** `Dispatch.type` checks, in the isolated world, that `ref`'s node is `getRootNode().activeElement` after `DOM.focus`. If not it ends `failed` / `focus-redirected` and sends no `Input.insertText`. The check runs after the page keys are read and before the final `admit`, and its failure is raised only after `admit` passes, so the verdict, `admit` and the send stay in one main-actor run (a human takeover that moved focus reports `cancelled`, not `focus-redirected`). Residual window: a page script that moves focus after the check's reply but before the renderer handles `Input.insertText` is not caught; closing it needs an insertion guarded inside the renderer.
- **Observe title:** `Observation.title` is the DOMSnapshot document title from the accepted collection, not `tab.title`, so a retried observation never reports the previous page's title.

## D16 · 2026-10-29 · Window chrome: shortcuts are menu key equivalents, matched by the app, not by AppKit
- **One list, one matcher.** Every shortcut (⌘T ⌘L ⌘W ⌘⇧T ⌃Tab ⌃⇧Tab ⌘1–8 ⌘9 ⌘R ⌘[ ⌘] ⌘D ⌘F and the Edit commands) is a main-menu item with a key equivalent. `NSMenu.item(matching:)` compares modifiers exactly and `BarestateApplication.sendEvent` sends the item's action once, before AppKit's own search. Measured: AppKit's search ran New Tab for ⌘⇧T (it ignores Shift for an item that does not list it) and did not match ⌃⇧Tab. CEF's `OnPreKeyEvent` claims the same events with the same matcher, so a page never hears a shortcut's key-up, or its key-down if one reaches the web view.
- **Key lifecycle.** Holding a shortcut fires it once; only Ctrl-Tab and Ctrl-Shift-Tab repeat. The key code of a consumed key-down is remembered, so its release never reaches the page even when the modifiers were let go first.
- **Human control.** Back, forward, reload and loading an address take control of the active tab (`humanInput`), as a click or key in the page does. Typing in the address field alone does not; the load does. Shortcut key-downs are not also counted as page input.
- **Typed schemes.** `javascript:`, `vbscript:` and `data:` (any case, tabs and newlines ignored, with or without `//`) are searched for, never loaded.
- **Crowded strip.** Tabs keep 208 pt and shrink to 96 as designed, then share the remaining room down to 40 pt so every tab and New Tab stay inside the window. Scrolling a strip of more than about 13 tabs is not built.
- **Edit commands go to the focused frame.** A CEF view does not answer `selectAll:`/`cut:`/`paste:` from the responder chain (measured: ⌘A selected nothing). The Edit items call `CefFrame::Undo/Redo/Cut/Copy/Paste/SelectAll` when the first responder is inside a tab and the first responder otherwise (address field, find field).
- **Last tab.** ⌘W on the only tab opens a blank tab first, so a window never has zero tabs. Closed tabs are kept for ⌘⇧T in a stack of 25 (URL, title, index); a tab closed by the page or the app is not kept. ⌘⇧T reopens at the original index, newest first.
- **⌘T is a placeholder for the launcher.** Until `frontend-launcher` lands, ⌘T opens a blank tab and focuses the address field. VAL-TABS-013/018 compare the launcher frames and cannot pass before that feature.
- **Address input.** Text with a scheme (or `about:`) loads as typed; a bare host loads over https (http for localhost and IPv4 literals); anything else searches with `settings.json`'s `searchEngine` (default DuckDuckGo, used only if it contains `%s`). History records only http/https pages after load; ⌘D toggles a bookmark for the current page.
- **settings.json** lives in the data dir and is created with defaults; an unreadable file is left alone and the defaults are used.
- **Fonts and art** come from the bundle: `Resources/Fonts` is copied to `Contents/Resources/Fonts` and registered at launch (process scope, `CTFontManagerRegisterFontsForURL`); `Resources/Art/kyoto-background.png` is copied in when present. Without it the empty area is ivory plus the fade.

## D17 · 2026-10-29 · Vertical tabs: one geometry source, a pure reveal state machine, an explicit key loop
- **One layout function.** `ChromeGeometry.frames(layout:mode:size:)` in the core gives the tab strip, sidebar, toolbar and content frames for every layout and mode; `WindowRootView` only applies them. Switching layout moves views and never recreates a browser, so page state survives (VAL-CROSS-003). The overlay floats at x 8, y 56, 224 wide and never changes the content frame.
- **Reveal rules are data.** `OverlayReveal` (core) holds five flags (pointer at edge, pointer in sidebar, menu open, drag, sidebar focus), a 0.12 s dwell to show and a 0.25 s delay to hide, and reports the next deadline. `AppController` arms one Timer on that deadline, so there is no polling and ten crossings give at most one show and one hide.
- **`test.pointerEdge` drives the model.** Synthetic NSEvents cannot make AppKit fire a tracking area, so the hook calls the same callbacks the areas call. A real tracking-area crossing is therefore not covered by the e2e tests.
- **Explicit key loop.** `rewireKeyLoop` chains toolbar, address, tab strip, sidebar rows and footer through `nextKeyView`, and `ChromeButton` and `TabItemView` handle Tab, Space and Return themselves: AppKit leaves buttons out of the loop without Full Keyboard Access and does not forward Tab from a custom view. A click never takes focus (`acceptsFirstResponder` is false during a left mouse down) so it cannot fight the drag hold or the page.
- **Menu titles refresh in `validateMenuItem`.** "Show Sidebar" / "Hide Sidebar" and the layout checks follow the model; `test.menu` calls `updateAll()` first, as AppKit does before showing a menu.
- **Settings** live in `settings.json` (`tabLayout`, `sidebarPinned`, `searchEngine`). The model status only reports whether a key exists (environment, then `BARESTATE_ENV_FILE` or `./.env`); its value is never read into UI, logs or hooks.
- **Launcher frame.** Checked once the launcher exists (D19): `e2e/test_sidebar.py` compares the launcher frame across reveal and pin.

## D18 · 2026-10-29 · bench.py reaps the code-sign clones its launches leave; the cefclient smoke is opt-in
Chromium copies a launched, freshly re-signed bundle (about 650 MB) into `$(getconf DARWIN_USER_TEMP_DIR)/../X/<bundle id>.code_sign_clone/` and removes it only on a clean exit; the cefclient test in `make e2e` left 13 GB there before it was cleaned. `scripts/bench.py` now snapshots the clone entries of the bundle it launches (cefclient for `cefclient-baseline`, Photon otherwise), and deletes the entries that appeared during the run once every process is stopped (`reaping_code_sign_clones`); older entries, other bundle ids and symlinked clone directories are never touched. Entry names are random, so a clone from another launch of the same bundle id during a bench is also removed. `stop_tree` already sends SIGTERM and waits 15 s before SIGKILL. The real cefclient smoke in `e2e/test_bench.py` runs only with `BARESTATE_BENCH_CEFCLIENT=1`; the cleanup logic has pure unit tests in the default run. Measured (`.logs/clone-*-{before,after}*.txt`): the clone dirs total 0 KB before and after one opt-in smoke (peak 337 MB sampled while it ran) and after one full `make e2e` (peak 343 MB, from Photon itself, removed on its clean exit); free space 2.79 GB before and after.

## D19 · 2026-10-29 · Launcher: ranking is a pure core function; the panel's inset is fixed per open; an empty Search opens the address field
- **Rank in the core.** `LauncherRanking.rank(query:snapshot:generation:)` takes value types and returns rows tagged with a generation; `LauncherModel` drops any answer whose generation is not the newest, so a late result never changes which row Return runs. The app ranks in a detached task and re-enters the main actor through the same check. The scan matches UTF-8 bytes over lowercase keys built once, which keeps a keystroke over 10k history rows near 10 ms (BENCH.md).
- **The inset is read when the launcher opens.** Design 2.2 centres the launcher right of a pinned sidebar, but VAL-LAUNCH-010 forbids the frame changing while it is open. The panel keeps the inset it opened with; the next open re-centres. Reveal, pin and unpin therefore never move it.
- **Search with an empty query.** Choosing it opens a blank tab and focuses the address field. A `?q=` search for nothing would load the engine's home page with no intent.
- **Start task is a pending run.** `run.start {prompt, origin, tabId}` goes into `RunController` (core `RunBook`), which records the run as `pending` and calls no model until agent-muse. `run.list` lists them. With `test.modelOffline` the row is disabled and the panel shows the error state.
- **Background lock.** While the launcher is open `performShortcut` consumes every menu shortcut except the ones in `LauncherController.allows` (New Tab, Settings, sidebar toggle, edit commands, quit/hide), and the full-window launcher view takes all pointer input.

## D20 · 2026-10-30 · E2E flakes fixed at the root; a crash is a test failure

- **Quit closes the Store explicitly.** `Store.close()` (actor) checkpoints, clears PERSIST_WAL and calls `sqlite3_close`; `main.swift` awaits it after the message loop. Relying on the last reference going away failed because a `Task` still suspended when `CefRunMessageLoop` returns is never resumed and keeps the Store alive, so `-wal`/`-shm` stayed behind (QuitTests under load). SIGTERM and ⌘Q share `requestQuit`, so one path covers both.
- **Synthetic-input timeout was a timestamp mismatch, not a dropped key-up.** On a locked screen (`CGSSessionScreenIsLocked` true on this machine) AppKit hands posted events back with the timestamp cut to nanoseconds, so `post()` never matched its continuation and waited the full 3 s per `test.key`/`test.type`. Stamps now sit on a whole-microsecond grid and compare as integers (`EventStamp`). With a key window nothing changed, and no branch on key state is needed. Measured on the locked screen: `test.key` 3.15 s to 1 ms, `test.type "hello"` 3.15 s to 5 ms; `test_launcher.py` (34 tests) 25 s, `test_sidebar.py` (14) 26 s.
- **Locked-session input is synthetic.** Results from a locked session show app logic only. They are not real-input or real-IME evidence.
- **Settings no longer leaves a stale key window.** Closing it returns key status to the main window (`windowWillClose`), and the edit/close/launcher paths test `SettingsWindow.isFront` (visible and key) because a closed window can keep reporting key.
- **Input-ready beacon.** Fixtures that receive the first synthetic click or key (`input.html`, `act.html`, `keys.html`) send `/__beacon?ready=1` after `load` and one `requestAnimationFrame`; the tests wait for it. A page can miss input sent before its first frame.
- **bench.py reaps only cefclient clones.** Photon exits cleanly and leaves none; its bundle id could name the user's own running copy. A cold-start with fewer than 10 warm runs prints `not enough runs for a budget verdict (n<10)`, never PASS or FAIL (the exit code stays 1).
- **Crash root cause: `NSApp.sendAction(_, to: explicitResponder, …)`.** With a non-nil `to:` AppKit sends the selector without checking, so a first responder lacking `cut:`/`copy:`/`paste:`/`selectAll:`/`undo:` (Settings window, a button) raised NSInvalidArgumentException; Chromium's NSApplicationCrashOnExceptions turned it into SIGTRAP (repro: ⌘, then ⌘X). `edit(_:native:)` now calls `firstResponder?.tryToPerform(_:with:)`, which walks the responder chain and may find no handler. Audit: the other `sendAction` calls (`performShortcut`, `test.menu`) target menu items built in `MainMenu`, whose targets are `AppController` or `NSApp` and implement their actions. Regression: `e2e/test_edit.py`; it crashed the app on the old code.
- **Harness guard (VAL-STABILITY-001).** `e2e/bs.py` snapshots `~/Library/Logs/DiagnosticReports/{Barestate,Photon}-*.ips` before each launch and `App.stop()` fails the test on a new report, a crash signal exit, or `uncaught exception`/`Terminating app` in stderr. App stdout/stderr always go to the test log dir (`BS_E2E_LOGDIR`, else a temp dir). `e2e/run.py` repeats the report check after the suite. Unit tests: `e2e/test_harness.py`.

## D21 · 2026-10-30 · Aggressive, privacy-safe logging; crashes are recorded before the process dies

- **Two sinks, one helper.** `Log` (app target) writes every event to `os.Logger` (subsystem `ai.barestate.photon`, one category per area) and to `<data-dir>/logs/photon.log` through `LogFile` (core, so rotation and `Log.origin` have unit tests). One rotated generation, 5 MB cap; rotation reopens onto the same descriptor number so the signal handler's saved fd stays valid.
- **What may be logged.** Ids, counts, Chromium error codes/names, `scheme://host`, journal states. Not full URLs, page or observation text, typed text, keys or tokens. Errors log their type and code (`Log.describe`), except the journal's own `Store.Failure` message. `e2e/test_logging.py` greps a run that loaded `input.html?q=...`, typed text and held a fake `MODEL_API_KEY` for any of them.
- **Crash capture, no swallowing.** `NSSetUncaughtExceptionHandler` and an override of `-[NSApplication reportException:]` log name, reason and `callStackSymbols` synchronously, then call `super` (Chromium's `NSApplicationCrashOnExceptions` still aborts). `sigaction` handlers for SIGSEGV/SIGBUS/SIGILL/SIGABRT/SIGTRAP write one preformatted line with `write(2)` to the pre-opened log fd and re-raise with the default action. CEF replaces these handlers inside `CefInitialize` (measured: the SIGSEGV line was missing until they were armed again after it).
- **CEF.** `log_file` is `<data-dir>/logs/cef.log` (it was `<profile>/cef.log`), WARNING by default, VERBOSE with `BARESTATE_LOG=debug`.
- **Harness.** `test.raise {kind}` exists only under `--test-hooks`. The harness copies both logs per test into `.logs/e2e/<ts>/<test id>/`, prints the photon.log tail and the newest matching `.ips` summary on failure, and reaps the crash reports of deliberate crashes at the end of the run (ReportCrash took 36 s for one).
- **Not logged yet.** Approvals and remote pairing do not exist in the app, so those categories have no events; the gateway's own connections appear as socket connects.

## D22 · 2026-10-30 · Photon shell: one window root, one way in, security from CEF

Supersedes the chrome parts of D12–D17 (toolbar, tab strip, sidebar, Kyoto empty area, tab layout); the launcher parts of D19 stay.

- **Names.** The bundle is `.build/Photon.app` (CFBundleName/DisplayName `Photon`); the executable, the CEF helpers (`Barestate Helper*`), the bundle id, the data dir and the socket keep their names, because the helpers are derived from the executable. `bs.APP_BUNDLE` and `run-app.sh` use the one path.
- **Borderless window.** Transparent titlebar, hidden title text, full-size content, no toolbar. `WindowRootView` is a canvas-coloured fill with the Lift mark and "Photon" wordmark, the page container, the page caption, the command button, the find bar and the launcher.
- **Interim layout.** Until the spatial canvas lands, the active tab's view fills `pageRect` (24 pt side margins, 72 pt top, room for the caption and the button below). Other tabs are hidden.
- **Command button.** A native `NSButton` (288×48, bottom centre, 16 pt inset) whose click calls `newTab()`, the same entry as ⌘T. While the launcher is open it is replaced by a compact ⌘T chip. ⌘L opens the launcher too (prefill belongs to the launcher feature).
- **Security.** `BSCef sslStateInBrowser:` reads `GetVisibleNavigationEntry()->GetSSLStatus()`; `PageSecurity` combines it with the scheme (Secure, Not secure, Local file, Certificate error). A refused certificate leaves a `chrome-error:` page with no certificate of its own, so `loadFailed` remembers the failure (net errors −200…−217) and the host it refused until a different page arrives. Certificate error always wins over Secure.
- **Exact shortcuts.** `ExactKeyMenu.performKeyEquivalent` returns false. `performShortcut` already runs every exact match, so what reaches AppKit's own search is a near miss (⌘⇧L would run ⌘L).
- **Bookmarks.** ⌘D is "Bookmark This Page" and `Store.addBookmark` is idempotent: a second press leaves one row. It is disabled, with a tooltip, when there is no page.
- **Lift mark in code.** `Design.liftMark(height:)` draws the two original Lift paths, so the About panel and the window need no image resource. Kyoto art no longer ships.
- **Settings close.** `test.ui.settings.closes` counts closed Settings windows and the e2e waits on it. With test hooks, `show()` activates the app first; an inactive app never made the window key, which was the one-off "timed out waiting for Settings closed".

## D23 · 2026-10-30 · Photon turns Chromium's code-sign clone off; the e2e harness reaps and fails on leftovers

- **What it is.** Chromium on macOS (feature `MacAppCodeSignClone`, CEF 156) clones the launched bundle (~335 MB) into `$(getconf DARWIN_USER_TEMP_DIR)/../X/dev.barestate.browser.code_sign_clone/code_sign_clone.<random>/` and removes it itself, a moment after the process exits, only on a clean exit. It exists so code-signature checks keep working when an app is updated in place while it runs. Photon is never updated that way.
- **Measured on `.build/Photon.app` before the fix.** The clone appeared at launch (335 MB) and ⌘Q, SIGTERM and `scripts/stop-app.sh` all removed it within about a second. SIGKILL of the app left it. In `make e2e` the clones that survived came from the deliberate-crash tests (`test_logging` SIGSEGV and uncaught exception: the crashed process still holds the clone while ReportCrash runs, and nothing removes it afterwards). The 13 GB run and the 335 MB entry of pid 16169 were launches that ended in the SIGTRAP crash loop of 2026-10-30 (`research/crash-2026-10-30.md`) or in a kill, not a clean exit.
- **Decision.** Disable the feature: `BSApp::OnBeforeCommandLineProcessing` passes `--disable-features=WebContentsOcclusion,MacAppCodeSignClone`. No copy is made, so a crash, a SIGKILL or a hung quit cannot leak one, and nothing needs deleting at quit (so there is no cleanup to log through `Log`). No function is lost: `make e2e` passes (166 tests, 1 skipped) twice in a row.
- **Proof.** `e2e/test_code_sign_clone.py`: a running app, ⌘Q, SIGTERM and SIGKILL each create no entry in the clone directory. Two `make e2e` runs left the clone directory empty (`.logs/clone-e2e-disk.txt`). Free disk moved −978 MB and then +929 MB across the two runs (the first included a rebuild; other writers on the machine dominate the noise), net −49 MB; the 13 GB growth is gone.
- **Harness.** `bs.App.start` snapshots the clone directory and `stop` waits for Chromium's own removal, then deletes entries created since the snapshot that no process has open (`lsof` on the clone's executable names the owner, so a live copy of the user's own Photon is never touched) and fails the test if the exit was clean. `e2e/run.py` repeats the check for the whole run and fails with `LEAK:`. Entries that existed before the run are never touched. `scripts/bench.py` keeps its own reaping for cefclient, which still clones.

## D25 · 2026-10-30 · Page graph: popups become tabs through CEF's own popup path; edges only from real events

- **Graph.** `PageGraph` (BarestateCore, pure) mirrors `TabStore`: one live node per tab with a committed non-blank, non-`chrome-error:` URL, plus the 40 most recent closed pages as archived nodes (`tabId == nil`). ## D27 · 2026-10-30 · Preview cache: stamped captures, one decision point, memory only

- **Document key.** `Tab.documentKey` is the main frame's `frameId:loaderId` from `Page.getFrameTree` (the same value `observe` reports). It is read on every committed main-frame navigation (new bridge callback from CEF `OnLoadStart`, which also fires for reloads) and before and after every capture. Tabs with no node are not tracked, so the blank page a tab starts on never makes a new node stale. CDP `Page.enable` is not used.
- **Stale.** A key change on a tracked tab marks the node `stale` (a few ms after commit, measured by polling `test.ui` in `e2e/test_previews.py`); a new page starts `none`. The old image stays, dimmed by the presentation, until a capture of the new document replaces it. A revived archived page whose node still holds an old image is marked stale too.
- **Capture.** `Page.captureScreenshot` JPEG q60 with `clip` = the card's aspect cut from the top of the visible viewport and `scale` chosen so the JPEG arrives at the card's pixel size (440 x 300 gave 440 x 300). The result is stamped with the key read before the shot, decoded with ImageIO `CGImageSourceCreateThumbnailAtIndex` (pixels kept, `ShouldCacheImmediately`) in a detached task, and offered to the cache after the key is read again; the offer and the check that the tab and its node still exist share one synchronous run. A different key, or a page closed meanwhile, is dropped and counted in `rejectedStale`. Only a visible tab view is captured.
- **Cache.** `PreviewCache` (BarestateCore) keyed by node id: LRU by count and decoded bytes (`width x height x 4`), start 64 / 48 MiB, limits writable through `test.previews`. A single image over the byte limit is refused and the old entry stays. Viewing a preview (`preview(for:)`) makes it most recently used. Eviction scans a 64-entry array, which is cheaper than a linked list at this size. Nodes leaving the graph lose their previews. The limits are not tuned yet: the footprint run belongs to the canvas feature that fills the cache with real card sizes.
- **Memory only.** No code path writes image bytes; `e2e/test_previews.py` scans the data dir outside `profile/`, new files in the temp dir, `lsof` of the app and the canvas tables for images and blobs after 10 captures.
- **Triggers.** Leaving focus and the settle-after-navigation capture are wired by the overview feature through `Previews.capture(_:cardWidth:cardHeight:)`.

## D33 · 2026-10-30 · `reportException:` is Objective-C: no Swift executor check on the crash path

- **Defect.** An NSException thrown inside a main-actor `Task` unwound out of the Swift job to `-[NSApplication run]`, whose catch calls `reportException:`. Nothing is swallowed.
- **Routes.** `action` (a view's mouseDown dispatched by the run loop) and `task` log `via=reportException` and end by SIGTRAP; a plain main-queue block (`exception`) never reaches the run-loop catch, logs `via=handler` and ends by SIGABRT. `e2e/test_logging.py` covers all three; `reap_crash_reports` records a deliberate-crash report of type EXC_BAD_ACCESS and `run.py` fails on it.

## D45 · 2026-10-31 · The run engine: one loop on muse-spark-1.3, the socket's own methods as its tools

- **Why.** Start task recorded a run and did nothing. The engine is the loop that makes it a run (architecture §5.10), built so mcp-server can reuse every call.
- **Shape.** `AgentLoop` (core, pure) takes `live`, `withinCap`, `model` and `tool` and returns `ended | stopped | failed(reason)`: each turn checks `live` then `withinCap`, calls the model with the function tools (tabs, observe, extract, action_status, open_tab, request_control, handoff, act), runs each returned call, and ends on a turn with no call. At most 40 turns (`failed: turn-limit`). `RunController` drives it and runs each tool through `RPCDispatcher.call`, the same handlers and gate the socket uses. It adds the run's `sessionId` (`<runId>.<launch>`: the launch part keeps a restart's `r1` apart in the journal and the ledger) and, for an act, a client action id. The computer tool is not a loop tool: Muse reaches it only through the act ladder's last rung (D40), so a `computer_call` can only become a point that passes admit and point acceptance.
- **Run states.** pending, running, waiting-approval (while an act of the run is `quoted`; the act tool polls `action_status` and returns the final row), then stopped, failed or completed. `RunOutcome.conclude`: completed only when the model ended the task and every write the run made is `confirmed`; a read-only run with a model stop is completed; any other write state, or no stop, is failed with the reason ("a write ended outcome-unknown: …", "the model did not finish the task"). Steps: one per observe, extract and act call, with state, plain-text reason and the journal row id.
- **Owner tab and takeover.** `run.start {prompt, origin, tabId?}` grants the owner tab to the run's session. `AppController.humanInput` captures the controller before it takes the tab back and calls `runs.takenOver(from:)`, so the run is `stopped` with reason `taken-over`, its approvals are withdrawn and nothing is dispatched or asked of the model, all before the input reaches the page. Ending a run for any reason (Stop, takeover, cap, failure) resolves its pending approvals `stale: run-ended` (the card leaves, quoted rows become cancelled) and hands its tabs back.
- **Cap.** A run stops at $2.99 of its $3 (`RunCap`), measured from the ledger entries labelled `<session>:` plus any test seed, before every model call and before every tool. The global $40 check and the ledger append stay separate steps (D39), so concurrent runs may overshoot by a call. The run fails `run-cap` without a call; other runs go on.
- **Safety checks.** A click's `pending_safety_checks` come back from `MuseGrounder.ground` unanswered (`SafetyAck`), are held per row, and are acknowledged once in the `computer_call_output` that follows: after `store.approve` for a quoted row (never for Deny or a stale row), and for an unquoted row only if admit would still pass. A screenshot-only turn that carries checks is answered with them at once, because there is nothing to hold back. The ledger shows the answer as the `:ack` entry.
- **Trail.** `museUsed(run, owner, used)` is called after an observe, extract or act call returns for the page it targeted, so an edge appears only after the first call on the target, once per (from, to, run), and never to the owner.
- **Model.** Grounding asks for up to 1000 output tokens (400 cut the contributor's answer off before its click). A 5xx or 429 is tried once more after a second (`ModelError.isTransient`; nothing was billed). A 400 for a response id the provider does not hold is not retried with the same id: D54. Provider error text is cut to 200 characters after the active key is replaced with `[redacted]`. Baseten has no computer tool and no `previous_response_id`, so the loop does not work under `BASETEN_API_KEY` (accepted; D3 keeps it an adapter).
- **Test hooks.** `test.holdModel {on}` and `test.runCost {usd}` (user-testing.md). The e2e harness removes `MODEL_API_KEY` and `.env` unless `BARESTATE_LIVE_META=1`, and under test hooks the Keychain is not read, so a started task cannot spend by accident.
- **Evidence.** `e2e/test_run.py`: deterministic (lifecycle, Stop and takeover withdraw the card, cap, no model); live (read-only and write runs, a sensitive act waiting for approval, trail edges, the Muse rung, no-match, mid-call takeover, safety checks on Allow and Deny). Live cost per test is in the handoff.
- **Not done here.** Run rows, labels, the activity view and run motion (runs-task-ui, runs-motion-fidelity-cross), the MCP server, the phone path.

## D57 · 2026-10-31 · The gateway: one process, stateless MCP over HTTP, hashes only, a sliding window for the rate limit

- **Shape.** `barestate-gateway` is its own process (Network.framework `NWListener` bound to `127.0.0.1` only, `--port` default 47820, `--socket`, `--public-host`). Pure parts live in BarestateCore and are unit-tested: `HTTPHead` (Content-Length only; a second Host, Origin, Authorization or Content-Length, or any Transfer-Encoding, is refused), `GatewayPolicy` (Host and Origin, 403 before auth), `GatewayRoute`, `SlidingWindowLimiter`, `MCPBridge`, `PairingStore`. Order per request: Host/Origin, token, rate, method, body size.
- **MCP over HTTP is stateless.** Each `POST /mcp` opens its own connection to `app.sock`, sends one line and reads one line (502 with a JSON-RPC error if Photon is not there). `MCPBridge` passes only `MCPServer.methods` and overwrites `_meta["barestate/session"]` with `http-<first 8 hex of the token hash>`, so a remote client can neither pick its session nor reach `approval.decide`, `control.decide` or `run.start`.
